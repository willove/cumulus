# synthesize_roi — 证据合成（带引用，无证据拒绝）

将证据窗口合成为结构化 Markdown 简报，引用必须来自证据，禁止编造。

## 输入
Query: "{{query}}"
Evidence:
{{evidences}}

## 输出
只返回一个 JSON 对象：
{
  "summary": "带 [n] 引用标记的同语言 Markdown 简报",
  "citations": [{"index": 1, "quote": "原文片段"}],
  "confidence_note": "证据充分|证据不足",
  "refuse": false
}

## 规则
- **简洁为默认**：直接回答问题，不加多余展开。简单事实题（"X是什么/多少/谁"）用 1-3 句话回答。只有问题本身要求详细列举时才展开。禁止添加用户没问的背景、关联知识、延伸解读。
- 每个关键断言后标 [n]，n 对应 Evidence 顺序。
- **结构化简报**：summary 用 Markdown 标题分节、要点分条，不要输出无分段的大段散文。凡列举类内容（情形、行为、条件、标准、类型、步骤），逐条附上原文中的**条款号**与**关键参数**（期限、数额、年龄、幅度、比例等原文给出的具体数字）；同类列举达三项及以上时用 Markdown 表格呈现（列如：类别/条款/行为或条件/期限或幅度）。先总述结论或框架，再展开列举。
- **专名只准来自证据窗**：人名、地名、器物名、称号等专名必须逐字取自 Evidence 原文，不得凭你对该领域的既有知识补全或改写（实测反例：改写语料中师父已更名，摘要框架句仍写原著名——知识渗漏；证据只写"祖师"时不得自行写成"菩提祖师"）。证据未给出专名时用原文使用的称谓。
- 证据不足或与 Query 无关时 refuse=true，summary 说明缺口，不得编造数字/步骤。
- 语言跟随 Query。

## 冻结回归
- 无证据 → refuse=true。
- 有直接答案证据 → summary 含 [1] 等引用且 citation.quote 为证据子串。
- 列举类证据 → 条目带条款号与关键参数，不用大段散文。
- JSON 可解析。
