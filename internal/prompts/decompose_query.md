# decompose_query — 原子事实拆解（B1 的生产实现）

把用户查询拆成检索系统应当**分别独立满足**的原子证据需求。

## 背景：这一层为什么值得花一次调用

`Score >= 4` 决定一个窗口是否保留，`bestScore >= 8` 决定循环是否收束。历史上这两条线
吃的是一个**逐窗 LLM 打分**（0-10），实测在同一输入重复打分时中段（3~7 分）判决有
**36%~48% 会翻转**。于是"最弱需求"停机（`NeedContinue`）建立在一个抖动的覆盖集合上。

一次拆解的价值不是"多列几条关键词"，而是**让停机判据作用在一个稳定的 K 上**，而不是
让 K 本身由打分抖动决定。

## 输入
User Query: "{{query}}"

## 规则

1. **每一条必须能独立拿去检索**——一个完整、自洽的信息需求，不是原句的一个片段。
2. **禁止在下列位置切开**（这是历史启发式最常见的错法）：
   - 书名/篇名内部：`《…旅游服务与管理英语》` 的「与」不是分界
   - 法律术语或固定搭配内部：`领事保护与协助`、`保护`与`协助`是一个词
   - 单一枚举的并列项内部：`单位和个人`、`无线电报和无线电话` 是一个主语/一个术语
   - 词语内部：`未能及时` 中的「及」
3. **法律择一（"或者"）不是两个需求**——"数额特别巨大或者有其他严重情节的判什么刑"
   是一个问题，不要拆。
4. 只有一个需求时就返回**一条**（等价的整句）。**不要为了凑数拆**。
5. 上限 4 条，通常 1~2 条。宁可少拆。
6. 每条不少于 4 个字。

## 输出
只返回一个 JSON 数组，元素是字符串，无多余文字：
["需求一", "需求二"]

## 示例

输入：实用新型和外观设计分别指什么？
输出：["实用新型的定义", "外观设计的定义"]

输入：《中等职业教育特色精品课程规划教材：旅游服务与管理英语》共编写了多少个单元？
输出：["《中等职业教育特色精品课程规划教材：旅游服务与管理英语》共编写了多少个单元"]

输入：连接池最大连接数是多少
输出：["连接池最大连接数"]
