# web 内容审计（重建前必读）

> 状态：v0.1 · 2026-10-07 · 输入：cumulus 的 v3–v8 六版 UI 历史、`docs/flow-grammar.md`
> 结论先说：技术栈维持 Vite + Vue；**内容不整体搬迁，按本审计逐块判去留**；契约先于页面。

## 一、审计方法

三把尺子，每块内容都要过：

1. **它对应哪个流程**——不对应 qa/eval/learn 任一流程、也不属于“语料/引擎”运营面的，是残留，砍；
2. **它的契约是什么**——说不清自己读哪个字段、调哪个面的，是漂移源，重建前必须先定契约；
3. **它上一版为什么活下来/死掉**——六版里反复出现又反复被拆的（库管理、测试一问），说明归属一直没定，这次按尺子 1 归位，不许再“放着先”。

## 三、新增：两个 UI 家（旧 UI 没有、新文法要求的）

1. **status 面**（放引擎页顶部）：“依赖显式、不静默失效”需要界面。渲染 `Context.Dependencies()`：每个可选组件（信念、词表桥接、MCS 采样……）声明依赖的 key 是否可用，不可用时在整个界面可见。旧 UI 的失败模式是组件悄悄不工作，用户以为系统坏了。
2. **提交视图条**（问答页答案下方）：每次回答的 committed view 四版本（语料/配置/策略/信念）。旧 UI 从来没有“这个答案是对着哪套环境给的”——不可比时只显示理由，不显示差值（照搬评测页的三指纹规则）。

## 四、重建纪律（六版 UI 的学费换来的）

1. **契约先于页面**：TS 类型由 Go 结构体生成（contract-gen 门），页面不允许手写接口类型。`conf/confidence` 那类漂移在生成时就死。
2. **令牌单一来源**：`web/src/tokens.css` 是唯一样式来源；业务 CSS 只准用令牌，不准写字面色值（v6–v7 的病因就是直接吃组件库的中后台默认色）。
3. **改布局先出参考图与要素表**：没有参考图不动布局；要素表（色板/字阶/间距/圆角/阴影）落成令牌后才能开工。这是 v8 用四张参考图才走对的路，固化成规矩。
4. **不出 v9**：以后只有 patches，不出版本号；每出一版暗示上一版作废的沉没成本滚雪球，停。
5. **浏览器门保留**：cumulus 的 browser-live 门（真点生产内嵌 `/ui/`）原样继承，五页各自有渲染级契约；它抓出过“多层全绿但接口断线”。
6. **AI 腔清零**：标题不加粗成口号、不写“赋能/一键/智能”类文案；界面文字是操作说明，不是宣传。

## 五、新 IA 提案（等评审）

| 页 | 主操作 | 对应流程/类 |
|---|---|---|
| 问答 | 问 | qa flow + 提交视图条 |
| 语料 | 管理语料与摄取 | ingest / 语料类 |
| 知识 | 复核簇 | knowledge 类 |
| 评测 | 跑一次 | evalfcore |
| 学习 | 看/放行一次受管变更 | learncore（v0.1 未接线，先占位） |
| 引擎 | 配模型、看账、看 status | modelprofile / usage / status 面 |

与 v4 五页的差别：库管理进引擎、学习独立成页、status 面上位。改动能说清每块的归属，不再“放着先”。
