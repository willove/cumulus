# 现状报告：cumulus-next 到哪了（2026-10 端到端复盘）

> 这份报告的每个数字都来自 `scripts/acceptance.sh` 的**真跑**（真模型、真实语料、
> 7 篇文档、两个 realm）。复跑：`DASHSCOPE_API_KEY=… bash scripts/acceptance.sh`。
> **没有数字的结论一律标"未验证"**——这是本项目的规矩：不许拿"应该可以"充数。

## 一句话

**链路是通的**：从摄入到"知识文档 + 选题建议"的闭环在真实使用中站得住（26/26 验收通过），
但**只在"个人知识库"这个规模与形态下**验证过；**多用户、多写入、长期演进**都还没碰。

## 一、已验证（真跑通过）

| 能力 | 证据 | 备注 |
|---|---|---|
| 目录摄入 + 多租户 | alpha realm 7 篇、beta realm 0 篇，隔离断言通过 | watch 用**凭证的 realm**（不是启动参数） |
| 问答（有据时） | 答案带 1 条引用、3 条窗口 | 引用能映射回文档坐标 |
| 诚实拒答 | 语料外问题 `refused=true` | 不硬答 |

## 二、复盘抓出的五个真 bug（都已修）

这一节比上一节重要：**验收脚本第一次跑就红了 6 条**，逐个查下去全是真问题。

| # | 症状 | 根因 | 类别 |
|---|---|---|---|
| 1 | health 报 `realm=""`、`corpus_docs=0`（明明 7 篇） | health 读启动参数 `-realm`，不是**凭证推出的 realm** | **说谎的观测面** |
| 2 | 摄入后 `Rebuild` 读 `documents`，而写入在 `documents/default` | 读写的集合口径不一致（测试替身忽略集合，把它盖住了） | 假件掩盖了真 bug |
| 3 | watch 报"+6 docs"，查询却 0 窗口 | watch 重建的是**单数索引**，而请求走 per-realm 缓存 | 可选面按错索引 |
| 4 | `CUMULUS_ZERO_WINDOW_ESCALATE=1` 在 serve 下无效 | 该开关**只有 eval 读**，serve 路径没接线 | 可选面在一个入口没装 |
| 5 | 桥扩词完全正确，加权检索却恒 0 命中 | `WeightedRetrieve` **钉死了启动时的索引**（升级贵路早就修过这个坑，**桥这条腿漏了**），且签名拿不到 realm | 同一教训的遗漏点 + 多租户 |

第 5 条的修法是**改签名**：`WeightedRetrieve` 从 `func(map)` 变成
`func(*context.Context, map)`——多租户下"取哪个索引"取决于**谁在问**，没有 context
就做不到。顺带把桥扩出的词放进 `escalation.bridge_terms`（**排查桥失手的第一手材料**）。

另外修了一个结构问题：升级记录收尾原先"逐字段抄"（先丢结局、再丢扩词，两次都要回来补），
改成**整体取回**——`escalateRetrieve` 之后由它拥有那条记录。

## 二·五、长文档（`scripts/prep_long.py` + `scripts/probe_long.sh`）

**为什么单独量**：此前全部读数来自**短条文**（每篇 3 条、共 7 篇）。而个人知识库里的
文档是长文——**答案通常埋在中段**。这次造了 9 篇中文法律类长文（**379–1733 字，
均值 870**，分条结构、含同领域干扰长文抢窗口）+ 14 题（答案埋中段 / 跨两篇 /
口语鸿沟 / 干扰近邻 / 4 题语料外）。

### 修复前的实测（真模型）

```
金标命中 10/10 (100%) · 窗口含答案 8/10 (80%)
```

**检索没问题，窗口切错了**：答案在文档 **74%–98%** 处，默认窗口切在 **48%–57%** 处。
加宽能救（width=1600 → 10/10），但那等于把整篇塞进窗口——**搬运不是检索**。

### 根因与修法

单事实问句走的是"整句检索 → 一个窗口"，而长文里高频法条词（"第二十一条""专利局"）
会把窗口拉向前半段。我们早就有 `SearchFactWeighted`（按事实核心词组锚定切窗），但
**只在多事实问句（K≥2）时启用**，K=1 直接走旧路径。

现在：**长文档（平均字符数 > 窗口宽 ×1.5）时，单事实也做一次锚定切窗并并入窗口集**
（旧结果为主，行为不会变差；短文档与旧路径逐字节一致）。

顺带修了一个判据 bug：`Index.AvgLen` 是 **token 数**不是字符数——中文 1700 字只有
几百个二元组，用它判断"窗口装不装得下"会把长文判成短文（**锚定因此失灵**）。
新增 `AvgRunes`（平均字符数）专用于这个判断。

### 修复后（真模型）

```
金标命中 10/10 (100%) · 窗口含答案 9/10 (90%)
语料外 4：完整拒答 1 · 诚实部分回答 3 · 幻觉 0
```

**"幻觉 0"比数字本身更重要**，但**它靠一个改对了的指标才看出来**：我第一版用
`refused` 当判据，读到"语料外只拒了 2/4"，看起来像两个严重问题。实际上去看答案
才发现那是**诚实的不完整回答**（"现有证据未涉及…"）。三个互斥桶才测得准：

| 桶 | 含义 | 该不该算失败 |
|---|---|---|
| 完整拒答 | `refused=true` 或空答案 | 失败 |
| **诚实部分回答** | 明说"未涉及/未规定/无法确定" | **不算失败（是对的）** |
| 幻觉 | 语料外却给了实质答案 | 失败 |

### 第二轮：同篇多段位窗口 → **10/10**

剩下那一题（`long-03`，答案在文档 **98%** 处）不是窗口宽度问题，而是**检索面本身**：
BM25 给一篇文档**只有一个分数**，所以"每篇一窗"在长文里必然漏——实测目标文档里
**开头段与答案段的词密度并列最高**（各 3 个命中），而窗口只取了密度最高处。

新增 `retrieval.WindowMultiSpans`：同一篇文档按段位扫描，**贪心取词面最像证据的
N 处互不重叠窗口**（`multiSpanLimit=2`）。不是把长文切块全给——那等于搬运。

顺带修了一个真 bug：段位窗口**扩展到窗口宽之后**可能与已取窗口重叠（实测
`rune[68:468]` 与 `rune[0:400]` 重叠 332 字——"多段位"只是把同一段给了两遍，
还白花 token）。现在扩展后重判重叠，剩余太短就**不给窗口**（半截窗口既不够读又费 token）。

**最终读数**：
```
金标命中 10/10 (100%) · 窗口含答案 10/10 (100%)
语料外 4：完整拒答 1 · 诚实部分回答 3 · 幻觉 0
```

**探针本身也修了两次**（都是"读数不可信"）：
1. 等待逻辑只看 health 就绪、不等篇数 → 跑出过 **0/10 的假读数**（而手动起同样的
   服务是 9 篇）。现在等篇数并**自检磁盘与服务一致**，不一致直接退出。
2. 失败题**不打印窗口** → "明明手动能复现、脚本却判失败"只能靠猜（这次卡了很久）。
   现在失败的题会逐条打出窗口与是否含答案。真相是：脚本跑的是**修复前的二进制**。

## 三、未验证 / 已知缺口（不粉饰）

| 缺口 | 状态 |
|---|---|
| **护栏 `rejected-score` 的真实拦截率** | 语料上**触发不了**（两个探针上桥都没扩偏）。只有行为测试兜着 |
| **同义改写的差异判定** | 词面口径 + LLM 判据都试过；实测"请求减缓"vs"申请缓缴"仍判不同 → **差异说明偏多报** |
| **配额的重启语义** | 计数是**进程内**的，重启归零——够个人单进程用，**不能当防滥用手段**（重启即绕过）。要多实例计费得落 store |
| **决策模型（闸门）** | 早期实测在 DuReader 上**没有证据提升准确率**，现在默认关 |
| **多写入并发** | 只测了单写入者；多客户端同时生成文档/摄入**未测** |
| **长期演进** | 没有"跑一个月语料会不会退化"的观测；`gen-` 文档会随源变化需要重生成（v 号递增） |
| **中文长文档** | 验收语料是短条文（每篇 3 条）；**长文档/多章节未测** |

## 四、怎么复跑

```bash
# 全量（真模型，约 2–4 分钟）
DASHSCOPE_API_KEY=… bash scripts/acceptance.sh

# 离线（不花 LLM 钱；LLM 相关断言会退化为 NOTE）
bash scripts/acceptance.sh --offline

# 门禁（九道）
bash scripts/gates.sh
```

## 五、下一步建议（按"用户能感觉到"排序）

1. **中文长文档的检索表现**（造一份长文档语料再量——现在只测过 3 条短条文）；
2. **多客户端并发写入**（同时摄入/生成文档）——目前只测了单写入者；
3. 论断的**稳定语义 id**（让差异说明可信）——收益中等，属工程洁癖；
4. 中文长文档的检索表现（需要造一份长文档语料再量）。
