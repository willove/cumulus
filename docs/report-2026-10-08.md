## 一、结论

1. **项目自身完成度**：骨架级约 90%，按"v0.1 可用的本地问答工具"口径约 75%。三流程（问答/评测/学习）与 CLI/HTTP 面全部跑通；缺口集中在 web 只做了 1/6 页、以及"越用越准"只采集不消费。
2. **与研究线 v0.2 的偏差**：方向没偏，重心偏了——"证据供给层"超额完成，"harness 治理层"（提交视图、自进化闭环、权限/审计、热插拔）基本停在文法上。硬偏差 6 处、半落地 6 处、未落地 8 处（详见 §四.6）。
3. **本会话落地**：研究线 v0.2 的 P0 五项全部实现并进门禁；接入两套外部中文数据集；**抓到并修掉 5 个真 bug**，其中两个是产品级（检索分词、评测档案存储），一个正好卡住校准集计划。
4. **校准集问题有了可执行答案**：难度可由 hard negative 控制（DuReader 三档 93.8% → 80.8% → 45.9% @top-3），`hard` 档落在 30–70% 的校准可用区；但**当前置信度在难语料上非单调**，拟阈值之前必须先改特征。

## 四、抓到的 bug（按严重度）

### 4.1 检索分词器的脚本边界（产品级，影响 10% 真实问句）

`retrieval.Fields` 把 CJK 与字母数字攒进同一个 run，只在段首判一次切不切二元组 → 混排文本整串变成一个词、df 恒 0：

```
Fields("iphone6照片流在哪") == ["iphone6照片流在哪"]   // 一个候选都取不到
```

DuReader 上 **45/449 问句零候选**（iphone6照片流 / soc / ie / linux / gtx960 / wifi / 8月…），症状是"拒答"，根因是分词。修复：脚本边界即词边界。

| 档 | evidence@3 前 → 后 | @top-9 | 拒答 |
|---|---|---|---|
| DuReader easy | 83.5% → 93.8% | 87.1 → 96.9% | 46 → 0 |
| DuReader mid | 71.5% → 80.8% | 85.5 → 94.2% | 46 → 0 |
| DuReader hard | 43.4% → 45.9% | 63.9 → 70.4% | 45 → 0 |
| CMRC @top-3 | 96.5/95.0/92.0 → **99.0/96.5/95.0** | — | 6 → 0 |
| cn-law 300 | 74.0%（无回归） | — | 0 |

策略版本随之升 `qa.v0.2`（检索语义变了，两版答案不许混在一张表里）。落点：[tokenize.go](internal/retrieval/tokenize.go)，两条回归测试钉死混排分词。

### 4.2 评测档案撞引擎单值上限（阻塞校准计划）

449 题 × 9 窗 = 1.05 MB，撞 Badger 在 **in-memory 模式**的条目上限 1 MiB（`maxValueThreshold`，内存引擎没有 value log 可外溢；落盘模式上限是 `ValueLogFileSize` ≈1 GiB），在**第 253 题处**炸掉。**教训：不是引擎的问题（1 MiB 不是 cumulite 的规则，是 Badger 的），是我们的用法**——把随题数线性增长的档案塞进一个值，而引擎的模态划分本来就是"文档=内容，KV=小值"。修复即 §2.3；顺带把写放大从题数平方级降到 O(1)/题。实测 449 题与 **1,500 题**（校准计划规模）都跑通。

### 4.3 底物错配判据：四步走完才收敛

1. **死标签**：定义了 `SubstrateMismatch` 却没有任何规则返回它；
2. **半接线**：评测执行面没接查询分析，`OOV` 恒空 → 仍不触发；
3. **误标**：改用"过半内容词语料外"后，把项目自己的演示题"成本结构怎么样"判成底物错配（`learn` 的演示因此从"召回不足→topk 提升"变成 `nothing-to-learn`）。根因：**拿桥的触发器当失败标签**——`OOVShare` 是词表桥的开关（有任一句外语料词就该触发），判据的松紧要跟用途匹配（触发器要宽、失败标签要窄）；
4. **收敛**：`query.NoSharedContent`——问句内容词（去停用词、去胶水）在语料里一个都找不到才算零共享；`corpus == nil` 不判。DuReader hard 上只标 1/449，演示恢复。

### 4.4 其它两处

- **内联 `cumulus eval` 一直 panic**（老 bug）：不带 `CUMULUS_REALDATA` 时指纹是占位串 `"inline"`，打印处硬切 `[:12]`。改成内容寻址真指纹 + 安全截断。
- **升级重判丢校准来源**（上一轮新代码）：`routeWith` 重建路由决策时丢掉档位/程序/阈值 → 服务面凡走过升级的题 `committed.calibration` 全空。修 + 回归测试。

### 4.5 门禁的两次拦截

- file-size 门迫使两个越限文件按职责拆分（[api.go](internal/api/api.go) → [views.go](internal/api/views.go)；[qa.go](internal/qaflow/qa.go) → [runner.go](internal/qaflow/runner.go)）；
- 端口加 `Query` 打破三个测试替身 → 编译期红，逐个补齐（"加方法要负责"）。

### 4.6 与研究线 v0.2 的偏差清单（回溯结论，未在本会话修）

硬偏差：提交视图在服务面曾是空壳（已修）、痕迹信号闭环未合、belief 摘除未按原设计重做、草稿→重路由回路不存在（BioHarness 只搬了"升级"没搬"草稿判定"）、底物错配曾是死标签（已修）、Cordis 的 fiber 生命周期/热插拔/合流缺席（合流测试已补 context 层）。
未落地：deepseek-harness 四件（hooks/sandbox/session/extensions）；12 类上下文缺"知识簇/模型配置"两类，另有五类变形；realm 未上服务面；拦截/权限未实现；LLM 合成路径把证据原文送出本机（offline 合成不出网）。
