# ADR-001：Go 下不做代码级热模块替换

- 状态：接受
- 日期：2026-10-07

## 背景

Cordis 论文（arXiv:2608.25512）的核心机制之一是热模块替换（HMR）：组件在运行时被换掉，
系统不重启。DeepSeek Harness 把整个 Cordis vendor 进去享受这一点。

## 决策

cumulus-next **不实现代码级 HMR**。

## 理由

1. Go 运行时不支持卸载已加载的代码。`plugin` 包只支持动态加载不支持卸载，
   且工具链限制多。硬做只能在进程级重启，那恰好是论文里被批评的粗粒度方案。
2. 论文的四原语在本项目真正要吃的是**状态可逆**（缓存、连接、证据窗口、策略实例、
   配置修订），不是代码可换。这些在 Go 里用注册/释放 + LIFO 反卷完整覆盖。
3. “热插拔”落到本项目的定义：换接口实现 + 记录版本号。提交视图记下这次处理用的
   是哪一版策略/配置/语料/信念；回滚 = 反卷注册 + 切回旧版本，不是重新加载模块。

## 后果

- 好处：全部保证可用可测；不碰 Go 的插件机制。
- 代价：改检索策略的代码仍要重新发布进程（部署频率以天计，可接受；
  以分钟计的调参走配置版本，不走代码）。
- 未来若真需要分钟级换代码，路径是 sidecar 进程 + RPC（论文 §6.2 的跨进程调用），
  不在主进程里硬凑。届时另立 ADR。
