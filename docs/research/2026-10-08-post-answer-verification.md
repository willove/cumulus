# post-answer verification：答案级信号能不能预测正确性

> 日期：2026-10-08 · 状态：H1 已验（**分域：单跳成立 / 多跳不成立**），H2 未做（缺锁箱复验），H3 未做 · 工具：`internal/calib`（AUC/阈值包络）、`judge.Points`（分点覆盖判官）

## 问题

现有路由信号全是**检索侧**的（查询覆盖度、候选边际、死路率、它们的加权组合）。
它们答的是"窗够不够"。而正确性取决于"**这句答案有没有证据**"——两个问题不同。
研究线里对应的说法是 SLC 的带符号接地（prediction-aligned）与 BioHarness 的弃权：
见证要落在生成器实际给出的答案上，而不是它读过的材料上。

**H1**：答案级验证信号（分点判官给出的要点命中比例，下称 `verify`）比检索侧信号
**更能预测正确性**；如果成立，它就能撑起一个可校准的拒答阈值（H2），接进路由后
拒答会更准而不是更少（H3）。

## 方法与一处自我陷阱

把 `verify` 变成一等信号（`evalfcore.Verdict.Coverage` → `ItemResult.JudgeCoverage`），
与五个检索侧信号一起进 `cumulus eval` 的信号竞赛表；区分度用 **AUC**（排序能力，
与阈值无关），不用"某阈值下的准确率"（阈值被挑过，天然乐观）。

**陷阱（先说，因为它是本节最有价值的部分）**：`verify` 的命中比例**就是判官判
YES/NO 用的那个数**（OK = ratio ≥ 0.6）。拿它预测**判官的决定**必然满分——
真跑确实给出 AUC(judge) = **1.000**，看着像完美信号，其实是同义反复。所以竞赛表
**并排打两列**：`AUC(judge)`（循环口径，只作对照）与 `AUC(证据)`（独立标签：金标
doc 有没有被引用，确定性，与判官无关）。**能回答 H1 的只有后一列。**

## 结果（DomainRAG multidoc，48 题，LLM 臂，39 题判上分）

```
signal            n   AUC(判官)  AUC(证据=独立)  lift@20%  单调    α=0.10
confidence       39     0.198        0.378          0.63    false      —
coverage         39     0.188        0.393          0.47    false      —
margin           39     0.379        0.426          0.94    false      —
support          39     0.629        0.540          1.26    false   14/0%
margin*support   39     0.383        0.443          0.94    false      —
verify(答案级)    39     1.000        0.535          1.26    true    31/0%
```

### 结论一：H1 证伪

在**独立标签**上，`verify` 的 AUC = **0.535**，与词面 `support`（0.540）基本同档，
都只是略高于随机（0.5）。**"答案有没有证据"并不比"答案的词面像不像窗里的话"更能
预测金标被引用**。这一条与本轮此前的三次证伪（LLM 重排、协调因子、覆盖度自适应加宽）
指向同一件事：**多跳问题上的信息瓶颈不在打分能力**。

### 结论二：检索侧信号在多跳问题上**反向相关**

confidence 0.378、coverage 0.393、margin 0.426 —— **全部低于 0.5**，即"置信越高，
金标越可能没被引用"。机理说得通：多实体问句里，**只覆盖一个实体的干扰文档就能把
覆盖度拉高**，而覆盖全部实体的那篇金标反而可能排在后面。所以现有的复合置信度在
多跳任务上不只是"弱"，是**方向反的**——用它做路由会**系统性地把好问题送去贵路、把
有希望的问题直接答了**。这条此前只是"证伪三次"，现在是**有量化符号的诊断**。

### 结论三：单调性仍然值钱

`verify` 是唯一**单调**的信号，也是唯一在 α=0.10 下有可行阈值的（答 31/39、风险
0%）。AUC 只比 `support` 高一点，但它给出的曲线不违反单调，于是阈值包络能收口。
**对"能不能设阈值"而言，单调性比区分度更要命**——这也是 §calib 把 PAV 与风险包络
分开做的原因。

## 泛化到第二个语料：H1 分域成立（单跳成立、多跳不成立）

同一套实验搬到 DuReader hard（噪声网页语料，**单跳**为主，80 题、71 题判上分）：

```
signal            n  AUC(判官)  AUC(证据)  lift@20%  单调   α=0.10      α=0.20
confidence       71     0.650      0.576     1.24   false      —           —
coverage         71     0.574      0.576     1.11   false      —           —
margin           71     0.674      0.542     1.24   false      —           —
support          71     0.541      0.500     1.11   false      —           —
margin*support   71     0.672      0.538     1.24   true       —           —
verify(答案级)    71     1.000      0.635     1.73   true    41/0%      41/0%
```

两个语料放在一起，结论**不是"成立/不成立"，而是分域**：

| 域 | verify 的 AUC(独立) | 检索侧信号 | 读法 |
|---|---|---|---|
| **单跳**（DuReader hard） | **0.635**（最高） | 0.50–0.58（弱正） | verify 更好，而且**唯一能在 α=0.10 立阈值**：答 41/71、风险 0% |
| **多跳**（DomainRAG multidoc） | 0.535（同档于 support 0.540） | 0.38–0.43（**反向**） | verify 不比词面强；检索侧方向是反的 |

**合起来的判断**：答案级验证信号在**单跳问题上确实比检索侧信号强**（0.635 vs 0.576，
lift 1.73 vs 1.24，且只有它能立 α=0.10 的阈值）；在**多跳问题上它不解决问题**——
因为答案本身跨文档，"这段证据里答没答到要点"不是瓶颈（这与三补四十"多窗并集覆盖
67% 但选择器无用"是同一件事的两种说法）。

**这也修正了我上一节的措辞**：H1 不是被证伪，而是"在单跳域成立、在多跳域不成立"。
研究线 SLC 的带符号接地如果要用，得**按域分别声明**，不能当作全局开关。

## 未做与下一步

- **H2（阈值可校准性）**：两个语料上 α=0.10 都已有可行阈值（multidoc 31/39@0%、
  DuReader hard 41/71@0%），但**都还没在锁箱上复验**——mid 上就翻过车（21 题拟合的
  阈值在锁箱上错 20%）。锁箱复验是 H2 的必要一步，且那份锁箱看过就不能再调参。
- **H3（接进路由后拒答更准）**：未做。要做必须配哑臂对照（哑臂不加验证），
  否则"拒答变多"与"拒答变准"分不开。
- **该换标签再验**：现在的独立标签是 evidence（金标被引用），它测的是"检索对不对"，
  不是"答案对不对"。真正独立的答案级标签需要**人工核对的小集合**（≥30 题）——
  这是当前评测体系缺的最后一块，也是"判官不是唯一神谕"那句话的下一步。

## 边界

n 小（39）、单语料单任务、模型单一（MiniMax-M3.1-Flash-Preview）。以上结论**不是**
"答案级信号无用"，而是"在**证据命中**这个独立标签上它与词面支持同档"；换成人工
核对的答案级标签，结论可能不同——那需要下一轮的实验来判。
