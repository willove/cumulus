## 一、基本对象

| 词 | 含义 | 代码落点 |
|---|---|---|
| **上下文（context）** | 进程内唯一共享状态容器，每个集合/缓存/游标是它上面的一个 key | `internal/context.Context` |
| **命名空间（realm）** | 同一 key 在不同 realm 下解析到不同数据集（多租户） | `context.Realm`，由 `-ns` 传入 |
| **注册（registration）** | 往 context 放东西的唯一动作，必须同时给出逆 | `context.Registration.Release` |
| **提交视图（committed view）** | 一次迁移针对的环境快照，全程不变、可追溯 | `context.CommittedView`（四版本 + 校准档位） |

一次用户可见的处理（问答、评测、学习）是**一次迁移**：开始有目标视图，进行中只认开始时那一套环境，结束后留下提交视图。

## 二、流程一：一次问答（qaflow）

六个 stage，顺序固定。契约四元组：**读什么 / 写什么 / 逆是什么 / 怎么验证**。

| # | stage | 读 | 写 | 逆 | 验证 |
|---|---|---|---|---|---|
| 1 | 意图澄清 | 会话 | 改写 | 丢弃改写 | 改写可逆回原问；排序回到原问 |
| 2 | 证据供给 | 语料 | 证据窗口 | 窗口失效 | 引用可回溯到原文坐标 |
| 3 | 充足性路由 | 证据窗口 | 路由 | 丢弃路由 | 见 §2.1 |
| 3.5 | 升级执行（条件） | 路由 | 证据窗口 + 路由（重判） | 丢弃新窗口与路由 | 见 §2.3；路由非 escalate 时整件空过（留痕） |
| 4 | 合成 | 证据窗口 | 答案 | 丢弃答案 | 见 §2.2 |
| 5 | 记账 | 无 | 用量 | 红字冲销 | token 账平；上游不报 usage 即判成本未知并停止后续调用 |
| 6 | 学习（可选） | 用量 + 痕迹 | 信念 | 回退一版 | 护栏基线比对，掉线即回滚 |

**实现里的条件件与恒定件**（装配面见 `internal/qaflow/runner.go`，都是流程文法内的 stage，
不是旁路）：事实判定（证据后、驱逐前，恒注册）、上下文驱逐（证据与路由之间，恒注册）、
复用查（证据前）/复用记（记账后，成对，配了复用件才有）、弃权头（路由后，配了才有）、
改写 → 事实二次判定（升级后按最终窗集重算）。**哑臂装配**（`Options.Bare`）只留
意图澄清 → 证据 → 路由 → 合成 → 记账五步：零改写、零管理，是 §三.7 的最笨基线。✅

提交视图记四项版本：**语料、配置、检索策略、信念**；v0.2 起同记**路由档位与校准程序**
（`Calibration{Tier, Program, Threshold, ThresholdVersion}`）。✅ 服务面已落：`/v1/qa` 响应带
`committed` 字段，语料版本是内容摘要（`retrieval.Index.Digest`，改一个字就变），配置版本从
生效装配渲染（旋钮/可选件/校准程序），策略版本是标签，信念版本记 `none(belief-retired)`
——belief 已从检索路径退役（真语料 A/B 证实全局声望版有害），退役就要写在视图里。

### 2.1 路由规则（stage 3）

升级（FAST→DEEP）或拒答，只允许由下列信号触发，**分三档，按可用性自动降档**：

| 档 | 信号 | 可用条件 | 实现状态 |
|---|---|---|---|
| 优先 | **草稿置信度**：首 token 对数概率，温度校准后使用 | provider 返回 logprobs | ⏳ 未接（`internal/llm` 不取 logprobs；接上时改 `qaflow.TierLogprob` 并重校准） |
| 常备 | **接地检查**：答案或其内容词能否在证据窗口的原文 span 里对上 | 无外部依赖，永远可用 | ✅ 二值版（`SynthesizeStage.Verify` 引用可回溯 + `EvidenceStage.Verify`） |
| 兜底 | **检索侧置信代理**（覆盖度/区分度/死路率加权）；次选行为信号（停滞/重复） | provider 无 logprobs 时 | ✅ `qaflow.RetrievalConfidence`，档位记 `retrieval` |

置信度只是路由代理，不是正确性裁判，不得写进答案给用户看。provider 不返回 logprobs 时
置信度记"未知"（`RouteSignals.ConfidenceKnown=false`）——与 stage 5"不报 usage 判成本未知"
同款纪律。**档位必须随决策留痕**：把兜底档报成"草稿置信度"就是口径漂移，不是命名品味。

阈值不手调，两条来源：

- **升级阈值** = DEEP 臂在校准集上的经验准确率（CAUC）：`qaflow.Tau0FromDeepAccuracy`，
  程序名进 `RouteSignals.CalibrationProgram`。当前**默认仍是手工基线 0.5**，换 CAUC 要
  显式 opt-in（`CUMULUS_TAU0=<数>`）——因为 CAUC 的 τ₀ 作用在**校准过的正确概率**上，
  而兜底档的置信代理不是正确概率，先要有可靠性曲线（`evalfcore.CalibrationTable`）。
  ✅ 机制已落地（含单调性检查与 τ₀ 建议值输出）；⏳ 用真实校准集定值属下一步。
- **拒答阈值**用风险控制法（A-CRC-QA）：定目标风险 α 与正确性判据，校准集上按可靠度降序
  取前缀线性风险的单调包络，加有限样本修正 (1−α)/(n+1) 选最小可行阈值；**无可靠子集
  导致 α 不可行时显式报告，不得静默放宽**。⏳ 未做（需要 2 的校准集，与上面同一批工作）。

实际档位、校准程序与阈值版本进 committed view（`context.Calibration`，由 `flow.Runner.ViewHook`
在 Commit 前从路由信号回填——记的是**发生额**，不是调用方声明值）。现状（early stop、abstain、
covers 检查、widen 各有一份写死阈值）收拢为一份路由函数：输入（置信度, 接地, 任务类型），
输出（快速返回 / 升级 / 拒答）。**不允许在 stage 2 内部散落判断升不升级的分支**。

### 2.3 升级执行（stage 3.5，条件件）

路由判 escalate 时，跑注入的贵路取数（FAST→DEEP 级联），然后**用同一把
尺重判路由**：

- 够了 → fast，带新窗口进合成；
- 仍不足 → refuse（reason 记 "escalation exhausted"）——升级是补救机会，
  不是绕过充足性硬答的旁门；
- 没判 escalate → 整件空过，记 "route did not escalate"；
- 没配贵路 → 死标签，记 "no escalation backend wired"（遥测里可见，
  不许假装升级过）。

升级前后路由判据同一把尺（gatherSignals），贵路是注册件（BM25DeepEvidence
等），换底物不动流程。

### 2.2 合成规则（stage 4）

- 合成只读证据窗口与改写，不私开检索；要检索就退回 stage 3 重新路由。
- 答案里每个断言必须映射到窗口 id；映射不上的断言删除或显式标“无证据”。
- 输出头按任务类型约束格式（选择题/是否题/事实题/列举题各不相同）。
- 接地检查的目标形态是**带符号**的（SLC）：见证一律在生成器**实际给出的答案**上量
  （prediction-aligned），带符号分数 = 支持该答案的词面证据 − 支持最强竞争解释的证据；
  进路由做连续权衡而非硬否决。⏳ 未做（现状从二值起步）。
  两个实证坑要在做的时候一起带上：词面信号对**扰动脆弱**（错别字/域外输入错误率 3%→19%），
  须配"分布漂移即重校准"触发；**聚合风险会掩盖弱接地子组**，护栏要分子组看。

## 三、流程二：一次评测运行（evalfcore）

一次运行 = 一个 episode：

1. **冻结**：题集 sha、语料 sha、配置 sha 受理时定死；运行期间改业务语料不影响已冻结实验。
2. **隔离**：每次运行一个独立引擎实例，灌冻结语料原样；业务集合不写。
3. **登记化**：采集器、判官、对照臂都是可挂可卸的注册；换判官是卸旧注册装新注册，不是改运行器。
4. **落盘顺序**：逐题结果先落（`eval_items` 集合，一条题一个文档，写完不改），
   **运行清单最后写**（KV 一个小值）；清单里的完成数因此永远不领先于已落盘的结果。
   被 kill 的运行只报 interrupted，绝不冷启动重放。✅ 实现见 `internal/evalfcore/archive.go`。
   （v0.2 修正：原措辞要求"同一个 KV 值"——cumulite 的 KV 由 Badger 兜底，而
   in-memory 模式单值上限 1 MiB，档案随题数线性增长，449 题就撞墙；内容分开存
   是引擎的模态划分：文档=内容，KV=小值。）
5. **可比性**：三指纹不一致即判不可比，只列理由不列差值。
6. **合流测试**：注册化的组件用固定种子 RNG 生成随机装卸序列，每步断言三件事——
   **无悬挂**（被卸注册提供的 key 不在任何活跃注册的读集里）、**逆干净**（卸载前后状态差为空，
   "只增不改"类 key 除外）、**行为等价**（随机序列结束后跑冻结评测，结果与按最终注册集合
   静态装配一致）。这是合流性（Cordis 定理 80）的可执行化。✅ 已落地：
   `TestConfluenceRandomMountUnmount` 覆盖 context 注册与可选组件层（stage 层还没有运行期
   装卸 API，边界写在测试注释里），并已进 `scripts/gates.sh` 的 grammar-conformance 门。
7. **哑对照臂**：每次对照运行必含至少一个最笨基线臂（纯 BM25 top-k、零改写、零管理）。
   精致臂不赢哑臂不得上线。✅ 已落地：`evalfcore.ValidateArms` + `Arm{Dumb}` 注册表 +
   `qaflow.Options.Bare`（哑臂装配）+ 独立门禁 `dumb-arm-invariant`；`cumulus eval` 的
   A/B 输出新增 `bm25-bare` 臂与对哑臂的差值。

### 失败模式六分类（capture 时归类）

六类**都必须是可达的**：定义了判据却没有规则返回它 = 诊断词汇表变装饰（`SubstrateMismatch`
曾经就是这样）。归类规则见 `internal/evalfcore/failure.go` 的 `Classify`，判据全部来自
可观测事实；`TestAllCategoriesReachable` 钉死可达性。✅

| 类别 | 判据（可观测化） | 修复方向 |
|---|---|---|
| 底物错配 | 要数值却全是叙述文本（`AsksNumeric` 且窗内无可读数值），或查询的实体/术语全体语料外（`QueryOutOfCorpus`） | 换证据源/升级结构化查询 |
| 召回不足 | 正确证据没进候选；或因空手（无窗）而拒答 | 查摄取、分词、改写 |
| 接地失败 | 答案词在证据窗口对不上（引用核不掉） | 查合成约束、引用解码 |
| 路由误判 | 该升没升（快路硬答而规则分为零）；或**有证据却拒答**（过度拒答 = 路由漏） | 调 stage 3 的信号档与阈值 |
| 腐烂 | 手上有窗、预算没用完就提前给不确定答案（弃权头早弃权那类） | 查上下文管理频率、保进展感信息 |
| 超限 | 窗口或轮次打满 | 查驱逐策略、早停条件 |

**拒答不再一律算腐烂**：拒答是文法的诚实出口，账要记在造成它的那一步（空手 → 召回；
有金标却拒 → 路由）——把正确出口当失败会同时污染诊断与学习周期。

## 三·八、可降级决策层（decision as optional stage）

**定位**：决策模型（另一家族的专用决策面，`internal/decide`：选项 / 是否 / 分数 + 置信度）
是**可选增强**，不是依赖。它的架构价值不在"更准的打分"——本项目已证伪三次
"更聪明的打分"（清单式重排、BM25 协调因子、覆盖度自适应加宽）——而在两点：
**便宜**（~70ms / ~120 token，比合成便宜两个数量级，可放进每问的固定环节）、
**逐题一致**（同一份提示词对同一份材料给同一判断，比自由文本判官稳）。

**契约**（`internal/qaflow/decision.go`，三条不变式各有测试钉死）：

| 不变式 | 含义 | 测试 |
|---|---|---|
| **缺席不改行为** | 没配决策面（client=nil）时不决策、不报错，调用方拿到的输入输出**逐字段相同** | `TestDecisionAbsentIsNoop` |
| **失败不阻断** | 决策面 5xx / 超时 → 原样放行 + 留痕。**决策失败不是问答失败** | `TestDecisionFailureDegradesInsteadOfBlocking` |
| **降级必须可见** | `DecisionRecord{Applied, Reason, Source, LatencyMS}` 永远有值；"没接上"与"接上了但判不行"在读数里分得开 | `TestDecisionRecordsEveryOutcome` |

`Reason` 的取值是**有穷集**：`not-bound`（没接）/ `error:…`（失败）/ `ok`（判了）。
留痕进 `KeyDecision`，所以"有没有在决策"是**可查询事实**，不从日志里猜。

**候选层与各自的降级**（都还没启用；启用条件见 §四）：

| 层 | 判什么 | 缺席/失败时 | 状态 |
|---|---|---|---|
| **合成前闸门**（`answerable`） | 这些窗口里有没有答案？没有就别合成，去取更宽或拒答 | 放行（= 今天的行为） | 骨架就绪，未接产品路径 |
| **窗口分级**（GaRAGe 四级） | 每条窗口是 ANSWER/RELATED/OUTDATED/UNKNOWN | 窗口原样进合成 | 骨架就绪（decide.choice 已通） |
| **合成后验证**（`grounded`） | 答案的事实点是否都在窗口里有依据 | 照常交付 | 只在评测里用过（`CUMULUS_DECIDE=1`） |
| **拒答/升级判定**（`noul` + 阈值） | 该答、该升级、还是该拒 | 沿用检索侧信号 | 未实现 |

**为什么把闸门放在合成前**：合成后验证是"事后判分"，答都答完了；而"窗口里根本没
有答案却合出了很像样的答案"（真跑见过：9 条窗口全在讲 A，答案写的是 B 的建议）
只能在**合成前**拦住。闸门判据不需要金标、不需要人工标注，退化路径天然干净。

**未证明的东西（不许当结论用）**：决策模型**没有**提升答案准确率的证据（独立标签
AUC 0.640，α=0.10 仍不可行）；它在多跳任务上不比词面支持强（0.535 vs 0.540）。
它的闸门用途目前只有一条 60 题的量级读数，**闸门阈值 0.5 是占位值，必须按数据定**。

### 合成前闸门（decision-gate）：接好了、跑得通，但对本语料不够灵

**它是什么**：`GateStage` 插在**路由之前**，问决策面"这些窗口里有没有答案"，没有就
拒答（带原因）而不是合出答案。留在提交视图与每题留痕里。

**验收的读数**（DuReader hard，离线合成，40 题）：
```
gate(off)                          ← 没接闸门（默认）
gate(decided=40 blocked=0 {ok:40}) ← 决策真跑 40 次、判"有答案" 40 次、拦 0 次
```

**它没拦任何题，而且这是对的也是错的**：
- **对**：这批题的 top-9 窗口确实都含答案（evidence 57.5%），闸门不该拦；
- **错**：剩下的 42.5%（检索没找到答案的那些），窗口也是**同主题的噪声**，
  决策模型把"相关话题"读成了"有答案"，于是全部放行——**闸门对这个语料不够灵**。

这与 §三·补四十的诊断是同一件事的两种表现：DuReader 的干扰项是**同主题网页**
（而不是跨主题噪声），无论词法信号还是决策闸门，都容易把"话题相关"当成
"答案存在"。**闸门位点是对的（合成前拦），但判据在"同主题噪声"语料上会漏**——
真要它在这种语料上灵，判据得换成"答案的每个事实点是否都在窗口里有依据"
（逐点核对），而不是"能不能找到答案"（整体判）。这是闸门判据的下一个版本，
**尚未做、也未验证**。

**未证明的东西**（照写，不当结论）：闸门对答案准确率**没有**任何证据；40 题上
blocked=0，它的净效果目前是零。它现在的价值是**把"合成前该拦"这件事接进流程
并留痕**，等判据灵了再谈效果。

## 四、流程三：一次学习周期（learncore）

学习 = 一次**受管变更**，五阶段各是一个注册：

1. **观察**：取深遥测（决策、harness 动作、环境状态、结果连成的轨迹，不是只看最终分）。
2. **诊断**：把成本与失败归属到具体组件；失败按 §三 的分类归因，不许“统统算召回问题”。
3. **提议**：只动白名单旋钮，一次假设调用生成。
4. **评估**：冻结评测上对照跑，不过护栏不上线。
5. **提升**：护栏过才切，掉线即回滚，全程落盘。

纪律：只改 harness 运行条件，不改模型权重、业务语料、评测协议。重试 = 新的受管变更，不是原地重放。

## 四·补、使用信号（"长"那一半的地基）

真实使用落地的信号，两源、三族。信号只落本机文件（data/signals.json），
不出网；换机器不带，删文件即消失。聚合视图：GET /v1/signals 或
cumulus signals -data <目录>。

| 信号 | 源 | 语义 | 主人 |
|---|---|---|---|
| refusal_unsatisfied | 服务端推导 | 拒答之后用户又**原样**问了一遍（归一化后精确匹配） | 弃权质量 |
| answer_incomplete | 服务端推导 | 答过之后用户又**原样**问了一遍 | 答案完整度 |
| cite | 前端钩子（点引用） | 用户真看了这条证据 | 证据质量 |

纪律：
- 只记**原样再问**（归一化精确匹配）。换了问法不是再问——换问法是
  另一种信号（"拒答没接住"），语义上不能混，混了靶子表就失效。要
  记换问法族，等真实使用里有案例再加，不预先建。
- 无 session 的一次性问答不记（没有"再问"的上下文）。
- cite 是 fire-and-forget：点了就发，失败静默——信号是资产，采集
  失败不该影响用户看文档。
- 信号增生是资产不是依赖：落盘失败信号仍在内存里继续产，磁盘故障
  不拖死问答面。

信号的用法（下一阶段主线）：refusal_unsatisfied 的问句 = 弃权头的
靶子；answer_incomplete 的问句 = 覆盖/取证的靶子；cite 密集的
doc#span = 证据质量的靶子。**用不用信号做重排是 learncore 的受管变更
（白名单旋钮），不是这里的自动行为。**

## 五、六条不变量

1. **一切经过 context**：共享状态必须绑 key；没绑 key 的位置（游离计数器、隐式全局）是缺陷。
2. **注册必有逆**：给不出逆的注册不进主流程；逆在应用时那一个状态上有效，是作者的义务，runtime 不代保。
3. **依赖显式**：可选组件（信念、词表桥接这类）登记为 Activator，声明 Requires；上下文每次变化后由 context 分类（激活/停用/中性）并驱动转换，状态进 `Components()` 供 status 面——**不许静默失效**（cumulus 的 vocab 桥接撤除、MCS 不触发，死在没有这个分类器）。
4. **迁移有提交视图**：每次处理记录它针对的环境版本（四版本 + 校准档位与程序，见 §一；服务面在 `/v1/qa` 的 `committed` 字段）；不可比时只给理由。
5. **出界管不了**：已发上游、已给用户的数据，回滚不覆盖；合流只对状态成立。
6. **便宜信号优先**：路由/升级/早停/腐烂检测用轻量信号；贵模型只做内容生成。

驱逐初始参数（抄自 Volt 论文，**未在本项目语料实测，第一版实测后按数据改本文**）：同类语义去重 0.92；综合分 = 0.4 新近 + 0.3 成功 + 0.2 log 频次 + 0.1 密度；会话类聚类 ≥ 0.85 且 ≥ 3 条合并。

## 七、边界（诚实清单）

- 本文是文法不是实现；每个 stage 的算法细节在各自包的文档。
- 可逆性作用于状态注册；Go 卸不了代码，热插拔 = 换实现 + 记版本（见 ADR-001）。
- 失败六分类与驱逐参数是外部论文的迁移，本项目未验证；底物判据（`AsksNumeric` /
  `HasNumeric`）是文本侧代理，保守（宁漏勿滥），未在真实失败集上验分布。
- 学习五阶段的自动化程度是目标，v0.1 只有骨架。
- 三级信号档位里**优先档还没接**（provider 无 logprobs）；τ₀ 的 CAUC 机制已落地但
  默认值仍是手工 0.5——用真实校准集定值，与拒答阈值（A-CRC-QA）同一批工作。
- 合流测试目前覆盖 context 注册与可选组件层；stage 层还没有运行期装卸 API，
  那三句断言的 stage 版要等 stage 注册化。
- 带符号接地（SLC）、证据窗口四级分类（GaRAGe 的 ANSWER/RELATED/OUTDATED/UNKNOWN）、
  学习护栏的量化阈值（EvoC2F 的成功率/P95/重试率）都写在正文里，但**尚未实现**——
  标 ⏳ 的不许当已做。
